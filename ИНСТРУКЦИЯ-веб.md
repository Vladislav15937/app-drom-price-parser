# Веб-интерфейс: инструкция

Анализ наличия запчастей на drom.ru: сколько конкурентов торгуют той же деталью в Барнауле и по
Сибири, где рынок разрежен (можно поднимать цену), а где плотный (можно снижать).

Проверено вживую 08-09-2026 на текущей сборке — каждый шаг ниже пройден в браузере.

---

## 1. Запуск и адреса

Приложение запускается из IntelliJ IDEA (класс `ru.retail.service.Main`) — поднимается и веб-сервер,
и десктопное окно. Веб доступен по трём адресам, они показаны в серой полосе сверху:

| Адрес | Когда нужен |
|---|---|
| `http://localhost:8081` | на этом же компьютере |
| `http://192.168.0.43:8081` | с телефона или ноутбука в той же сети (адрес зависит от вашей сети) |
| `https://…trycloudflare.com` | снаружи, для заказчика |

**Публичный адрес меняется** при каждом переподключении туннеля — актуальный всегда в шапке
страницы. Если связь с сервером пропадёт, в шапке загорится красное «● нет связи с сервером N с —
переподключаемся…»; страница оживёт сама, как только сервер ответит.

## 2. Вкладка «Проверка по OEM» — быстро проверить одну деталь

1. **OEM номер** — номер детали, например `1237231020`.
2. **Тип детали** — начните печатать («подушк», «фара», «суппорт»), браузер подскажет варианты из 154.
   Название должно совпасть со списком: при опечатке появится «Тип детали „…“ не найден — выберите
   из подсказок», и прогон не начнётся.
3. **Компания на Drom** — `YARD86`, по ней отличаются наши объявления от чужих.
4. **Цена, ₽** — необязательно; помогает выбрать наше объявление, если их несколько.
5. Галочки (по желанию, см. раздел 4): «точный подсчёт», «с новыми».
6. Нажмите **«Проверить наличие»** — обычно 30–60 секунд.

Результат: цветная плашка с вердиктом, счётчики «Барнаул / Сибирь» и ссылка на наше объявление.

Пример проверенного прогона: OEM `1237231020`, тип «Подушка двигателя» → 🔴 **Дефицит**,
Барнаул 0 конкурентов, Сибирь 5.

**Вердикты:**

| Плашка | Условие | Что значит |
|---|---|---|
| 🔴 Дефицит | Барнаул < 4 **и** Сибирь < 10 | рынок пуст и дома, и по Сибири — можно поднимать цену |
| 🟣 Мало по Сибири | Сибирь < 10 | дома есть, по региону мало |
| 🟡 Мало в Барнауле | Барнаул < 4 | дома мало |
| ⚪ Конкуренция достаточная | иначе | рынок плотный — кандидат на снижение цены |

Сибирь сканируется, **только если в Барнауле меньше 10 конкурентов**: при плотном домашнем рынке
деталь заведомо не дефицит, и десять лишних запросов к drom экономятся. Прочерк в «Сибирь» означает
именно это, а не ошибку.

## 3. Вкладка «Анализ по каталогу» — прогон списка деталей

### 3.1. Загрузите каталог

**Файл каталога (CSV/XLSX)** — выгрузка из Bazon. Нужны колонки `Создан`, `Номер производителя`,
`Наименование`, `Запчасть`, `Марка`, `Модель`, `Цена`; желательно `Состояние`, `Ткацкая (свободно)`,
`Номер товара`, `Цена изменена в`, `Кто изменил цену`.

Сразу после выбора файла появляется таблица со статусом «Ожидает» и подпись
«Загружено из файла (старше 6 мес): N».

**В отбор попадают только те позиции, которые:**
- относятся к выбранному типу детали (по колонке «Запчасть»/«Наименование»);
- поступили больше 6 месяцев назад (колонка «Создан» — это дата поступления на склад);
- в состоянии «Контракт» и со свободным остатком на «Ткацкой»;
- цену которых не меняли больше 6 месяцев. Исключение: если последним цену менял **сам парсер**
  (`c2226_external_app`), достаточно месяца — после нашего −10 % деталь возвращается в отчёт через
  месяц, а не через полгода.

Если каталог загрузился пустым, посмотрите в консоль приложения — там строка вида
«Каталог [тип]: отобрано 0 … Пропущено: свежих N, нецелевых N, … цена менялась <6мес N»,
она прямо называет причину. Частые случаи: выбран тип, которого нет в файле («нецелевых» = все
строки), или по всем позициям недавно менялись цены.

### 3.2. Задайте параметры

- **Тип детали** — как на вкладке OEM, с подсказками.
- **«+ ещё тип»** — добавляет второй, третий тип в тот же прогон; выбранные показываются тегами
  «Типы в прогоне», удаляются крестиком. Каталог пересобирается по всем типам, и у каждой строки
  работают стоп-слова своей категории. Нужно, когда надо проверить пачку категорий за один запуск.
- **Компания на Drom** — `YARD86`.
- **Кол-во (0 = все)** — ограничение прогона. Строки сверх лимита помечаются «Вне лимита»: они
  не будут обработаны (это не зависшие строки).

### 3.3. Запустите

**«Запустить анализ»** — прогон идёт на трёх дорожках (три мобильных IP) параллельно. В статусе
видно «Анализ: 5 / 74 (дорожек: 3)», в строках — какая дорожка их считает: «Анализ (L0)…».

**«Стоп»** — прерывает прогон; деталь, которая уже считается, дорабатывается до конца.

Прогон живёт **на сервере**, а не во вкладке: страницу можно перезагрузить или открыть в другом
браузере — таблица, цвета, статусы и счётчик восстановятся. Пока прогон идёт, повторный запуск
отбивается.

Обратите внимание: после перезагрузки возвращается **результат**, но не заполненная форма — поле
«Файл каталога» окажется пустым, тип детали и «Кол-во» сбросятся к значениям по умолчанию.
Это не потеря данных: таблица на месте, отчёт и переоценка доступны. Для нового прогона файл нужно
выбрать заново.

### 3.4. Читайте таблицу

| Колонка | Что показывает |
|---|---|
| Номер товара | внутренний id Bazon |
| OEM, Запчасть, Авто | из каталога |
| Цена, ₽ | текущая цена в Bazon |
| Создан | дата поступления на склад |
| Возраст | сколько месяцев позиция лежит |
| Изменено в | когда последний раз меняли цену |
| Барнаул / Сибирь | число конкурентов; прочерк в «Сибирь» = не искали (в Барнауле ≥ 10) |
| Статус | вердикт с расшифровкой чисел |
| Моё объявление | ссылка на нашу карточку на drom |
| Переоценка | «да» — строка не окрашена, рынок плотный, кандидат на снижение цены |

Строки красятся по вердикту: красные — дефицит, фиолетовые — мало по Сибири, жёлтые — мало
в Барнауле, без заливки — конкуренция достаточная.

### 3.5. Скачайте отчёт

**«Скачать результат (.xlsx)»** — появляется после прогона. В файле 15 колонок: то же, что в
таблице, плюс «Тип детали», кликабельный «Номер товара» (если задан `bazon.item-url-template`)
и внизу итог «Итого позиций: N; на переоценку (−10%): M». Непрогнанные строки в отчёт не попадают.

## 4. Опции прогона

Все четыре — независимые: включаются по одной или все сразу. **Без них приложение работает так же,
как раньше** — это и есть режим по умолчанию.

| Галочка | Что делает | Когда включать |
|---|---|---|
| **точный подсчёт** | читает все страницы выдачи drom, а не первую (50 объявлений) | на плотных категориях: у рычага обычный режим показывал 40 конкурентов при фактических 85, точный — 76 |
| **с новыми** | считает конкурентами не только б/у, но и новые детали | когда важен весь рынок: много новых предложений — поднимать цену бессмысленно |
| **дубли OEM → приоритетный тип** | если одна деталь подошла нескольким выбранным типам, оставляет одну строку — из типа с большим `priority` в `analysis-profiles.yml` | при прогоне нескольких категорий с общими номерами (ступица и цапфа) |
| **по применимости** | ищет не по OEM, а по «тип детали + марка + модель» | для кузовных деталей: у части марок номер индивидуален, и по OEM рынок выглядит пустым. Пример: подушка Toyota Vanguard по OEM — 0 конкурентов и «дефицит», по применимости — 37 и «конкуренция достаточная» |

Точный подсчёт и «с новыми» есть и на вкладке «Проверка по OEM». Режим применимости там
недоступен: марки и модели в одиночном запросе нет.

## 5. Переоценка −10 %

Кнопка **«−10 % в Bazon (переоценка)»** появляется после прогона. Снижает цену тем позициям, где
рынок плотный (колонка «Переоценка» = да).

1. **«Посчитать»** — расчёт без записи: −10 % от текущей цены с округлением до 10 ₽. Показывает,
   сколько позиций изменится, и первые строки списка; полный список сохраняется в
   `reprice-preview_*.csv` (ссылка «скачать CSV»).
2. Проверьте список и нажмите **«Применить −10 % в Bazon»**.
3. Результат: «изменено N, ошибок M» и лог `reprice-applied_*.csv` (id, OEM, было, стало, статус).

Если расчёт сообщает «Нет деталей с „Переоценка=true“ и валидным „Номер товара“» — значит все
позиции прогона окрашены, то есть рынок по ним разрежен и снижать цену не из чего. Это нормальный
ответ, а не ошибка.

**Поле «Применить к первым N деталям»** — тестовый режим: поставьте 2–3 и убедитесь в результате,
прежде чем запускать на весь список. 0 — применить ко всем.

Запись **необратима**: цены меняются в учётной системе. Токен расчёта одноразовый — повторное
нажатие «Применить» не сработает, скидка не уйдёт дважды.

## 6. Автодисконт

Кнопка **«Автодисконт»** — скидка в пики спроса с возвратом цены в остальные дни.

1. **Дефицитом считать** — галочки «красные / фиолетовые / жёлтые». Критерий выбираете вы.
2. **Лежит не меньше, мес** — 12 по умолчанию: возраст с поступления.
3. **Скидка, %** — `-1` означает «взять по расписанию на сегодня»: чт 5 %, пт 10 %, сб 10 %, вс 5 %,
   в остальные дни 0 % (то есть откат к базовой цене). Можно задать процент вручную.
4. **Первые N (0 = все)** — тестовый режим.
5. **«Посчитать»** → сводка: какая скидка на сегодня, сколько позиций подходит, сколько отсеяно
   по цвету и по возрасту, таблица «базовая / сейчас / станет».
6. **«Применить в Bazon»** — запись; лог `autodiscount-applied_*.csv`.

**Скидка всегда считается от базовой цены**, а не от текущей: базовые цены хранятся в
`autodiscount-state.json`. Поэтому повторные запуски не множат скидку саму на себя, и возможен
откат — в непиковый день позиции возвращается ровно исходная цена. Расписание настраивается
в `application.yml`, блок `discount`.

## 7. Если что-то идёт не так

| Симптом | Причина и что делать |
|---|---|
| «Сайт не может обработать запрос» по публичной ссылке | туннель переподключился, адрес сменился — возьмите новый из шапки страницы или из `http://localhost:8081/api/v1/info` |
| В шапке «нет связи с сервером» | сервер занят прогоном или туннель моргнул; страница переподключится сама |
| Каталог загрузился пустым | смотрите строку «Каталог [тип]: отобрано 0 …» в консоли — она называет причину |
| Счётчик стоит, а строки «Вне лимита» | это не зависание: позиции сверх поля «Кол-во» в прогон не входят |
| «Порт 8081 уже занят» при запуске из IDE | приложение уже запущено — закройте предыдущий процесс |
| Прогон встал, в консоли «капча» | дорожка меняет IP автоматически; если не помогает — прокси в `drom.proxies` могли истечь |

## 8. API (для интеграций)

Все эндпоинты под `/api/v1`, Swagger — `http://localhost:8081/swagger-ui.html`.

| Метод | Назначение |
|---|---|
| `GET /info` | локальный и публичный адреса |
| `GET /profiles` | список типов деталей (154, по алфавиту) |
| `POST /catalog-item/submit` | анализ по OEM: `oem`, `company`, `profile`, `deep`, `includeNew` |
| `GET /job/{id}` | результат такого анализа |
| `POST /catalog/preview` | разобрать файл каталога без прогона |
| `POST /batch/start` | запуск прогона: `file`, `profile` (можно несколько через запятую), `limit`, `deep`, `includeNew`, `dedupOem`, `byApplicability` |
| `GET /batch/state?since=N` | состояние прогона |
| `POST /batch/stop` | остановка |
| `GET /batch/report` | отчёт .xlsx |
| `POST /reprice/preview` / `POST /reprice/apply?token=…` | переоценка −10 % |
| `POST /discount/preview` / `POST /discount/apply?token=…` | автодисконт: `colors`, `minAgeMonths`, `percent`, `limit` |

⚠️ Аутентификации нет: любой, у кого есть публичная ссылка, может запустить прогон и изменить цены.
Не публикуйте адрес шире, чем нужно.
